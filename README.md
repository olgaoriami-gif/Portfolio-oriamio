# Portfolio — 3D & Design Systems

Локальный портфолио-сайт на React + Vite + Tailwind CSS.

---

## Запуск локального сервера

Node.js устанавливается отдельно на каждом компьютере. В репозитории хранятся только `package.json` и `package-lock.json`, а папка `node_modules` создаётся локально.

После клонирования проекта открой терминал в его папке и один раз выполни:

```bash
npm install
```

Для запуска сайта:

```bash
npm run dev
```

Эти команды одинаковы на macOS и Windows. Если PowerShell на Windows не принимает команду `npm`, используй `npm.cmd`.

Сервер запустится и выведет URL, например:

```text
Local: http://127.0.0.1:5173/
```

Если порт занят, Vite автоматически возьмёт другой:

```text
Local: http://127.0.0.1:5174/
```

**Главное правило:** если не работает или `ERR_CONNECTION_REFUSED` — проверь, что Vite запущен и используй тот URL, который он реально вывел.

## Работа с проектами

### Структура одного проекта

```text
public/projects/{id}/
  cover.jpg          ← обложка карточки и раскрытого проекта
  content.md         ← текст, картинки, галерея
  process.jpg        ← картинка для markdown
  result-1.jpg
  result-2.jpg
  ...
```

### Добавить новый проект

1. Создай папку `public/projects/{id}/`
2. Положи туда `cover.jpg` и нужные картинки
3. Создай `content.md` с frontmatter-шапкой (см. ниже)
4. Добавь проект в `src/lib/portfolioData.ts` — достаточно одного id:

```ts
{
  type: 'project',
  id: '3d-1',
  category: '3d',            // необязательно — есть в frontmatter
}
```

Заголовок, обложка, год и категория подтягиваются из `content.md` автоматически
(путь к файлу — по соглашению `/projects/{id}/content.md`).

### Порядок и размеры проектов на главной

Файл `public/projects.order` задаёт и последовательность, и ширину карточек —
одна строка = `<id> [span]`:

```text
3d-4 12
ds-1 6
2d-2      ← без span — дефолт 6 колонок
```

- Порядок строк = порядок карточек; перестановка — перенос строки.
- `span` — ширина в колонках сетки 1–12.
- Строки с `#` — комментарии. Проект без записи — в конец списка.

### Frontmatter (шапка content.md)

```markdown
---
title: Название проекта
year: 2024
category: 3d
size: 6
cover: img-cover.png
---

# Название проекта
```

| Поле | Необязательно | Fallback |
|------|---------------|----------|
| `title` | да | первый `# Заголовок` в файле |
| `year` | да | бейдж с годом на карточке не показывается; поле уйдёт в фильтр по годам |
| `category` | да | категория из `portfolioData.ts`; значения: `2d` / `3d` / `design-system` |
| `size` | да | `6`; ширина карточки в колонках сетки **1–12** |
| `cover` | да | первая картинка `![]()` в файле |

`size` — это число колонок из 12: `12` = вся строка, `6` = половина,
`4` = треть, `3` = четверть, любое промежуточное значение тоже работает.
Слова тоже понимаются: `full`/`half`/`third`/`quarter` и дроби `1/2`, `1/3`, `50%`.
Для ровных рядов сумма колонок в ряду должна давать 12 (напр. `6+6`, `4+4+4`, `8+4`).

Минимальная высота карточки растёт с шириной; в одном ряду карточки
выравниваются по высоте самой высокой.
Порядок карточек задаётся порядком записей в `src/lib/portfolioData.ts`.

`category` нужна только для фильтра — на самой карточке не отображается.
Сам фильтр живёт в шапке сайта (на десктопе; на мобильном — в меню).

`cover` можно писать относительно папки проекта (`img-cover.png`),
абсолютно (`/projects/3d-1/img-cover.png`) или ссылкой (`https://...`).

Пути к картинкам в теле markdown тоже резолвятся относительно папки
проекта: `![](result-1.jpg)` ≡ `![](/projects/3d-1/result-1.jpg)`.
Имя файла может быть любым — ограничений нет.

### Markdown-контент (content.md)

```markdown
# Название проекта

## О проекте

Краткое описание проекта.

## Процесс

![Подпись к картинке](/projects/3d-1/process.jpg)

## Результат

![](/projects/3d-1/result-1.jpg)
![](/projects/3d-1/result-2.jpg)

---

### Инструменты

- Blender
- Geometry Nodes
- Cycles

> Цитата или важная заметка
```

Поддерживаемые элементы:

| Markdown | Результат |
|----------|-----------|
| `# Заголовок` | Заголовок проекта |
| `## Заголовок` | Заголовок секции |
| Обычный текст | Абзац |
| `![подпись](url)` | Картинка с подписью |
| `![N](url)` / `![N\|подпись](url)` | Картинка на N колонок из 12 (в галереях) |
| `![N@S](url)` | То же, но начиная с колоночной линии S (`@center` — по центру) |
| Несколько `![]()` подряд | Галерея (грид 12 колонок, равные спаны) |
| `- пункт` | Список |
| `> цитата` | Блок-цитата |
| `---` | Отступ 60px (30px на мобильном) |
| `--- (N)` | Отступ произвольной высоты — см. ниже |
| `**жирный**` | Жирный текст |

### Галерея на 12-колоночном гриде

Внутри `:::gallery` (и в автогалерее из подряд идущих картинок) работает
грид из 12 колонок — как у карточек на главной. Спан задаётся в alt:
`![8](a.png)` — 8 колонок, `![4|Подпись](b.png)` — 4 колонки с подписью.
Сумма спанов в ряду — 12 (напр. `8+4`, `4+4+4`, `6+6`).

```markdown
:::gallery
![8](wide.png)
![4|Подпись](small.png)
![4](a.png)
![4](b.png)
![4](c.png)
:::
```

Картинки в одном абзаце (без пустой строки) — один ряд-грид; через пустую
строку — отдельные элементы, которые грид раскладывает сам по спанам.
`cols=N` в `:::gallery{cols=N}` задаёт дефолтный спан `12/N` для картинок
без явного `![N]` (cols=2 → по 6, cols=3 → по 4).

### Высота рядов в галерее

Элементы одного ряда автоматически выравниваются по высоте — ряд берёт
высоту **самого широкого** элемента, остальные кадрируются
(`object-fit: cover`) и получается ровный ряд, как у карточек на главной.

Явную высоту можно задать атрибутом `height` в `:::gallery` — в единицах
колонок сетки (высота ряда = `height` ширин одной колонки):

```markdown
:::gallery{height=4}
![6](a.png)
![6](b.png)
:::
```

`height=4` → ряд высотой ~⅓ ширины галереи; `height=6` → половина.
Работает и для `<video>` внутри галереи.

### Вертикальные отступы (`---`)

`---` — невидимый спейсер. Число задаётся в **единицах шкалы отступов**
(1 единица = 4px, как в Tailwind): `--- (15)` = 60px. На мобильном
значение автоматически уполовинивается; явное мобильное значение — через
слэш `--- (N/M)`. Значение с единицами (`px`, `rem`, `vh`) применяется
как есть и не масштабируется.

Ставится на отдельной строке с пустыми строками вокруг. Маргины соседних
блоков не добавляются — зазор выходит ровно заданной высоты, в том числе
между обложкой и первым блоком.

| Запись | Десктоп | Мобильный |
|--------|---------|-----------|
| `---` | 60px | 30px |
| `--- (5)` | 20px | 10px |
| `--- (10)` | 40px | 20px |
| `--- (15)` | 60px | 30px |
| `--- (20)` | 80px | 40px |
| `--- (30)` | 120px | 60px |
| `--- (40)` | 160px | 80px |
| `--- (60)` | 240px | 120px |
| `--- (30/10)` | 120px | 40px |
| `--- (80px)` | 80px | 80px |

## Разрешения изображений

### Обложки карточек (`cover.jpg`)

Обложка занимает всю карточку (`object-cover`), каждая третья — на всю ширину.
Рекомендуемый размер для Retina: **1200–1500 px** по ширине.

Минимум: **600 px** по ширине.

### Картинки внутри markdown (галерея, процесс)

- **Ширина: 1000–1200 px** покрывает большинство экранов
- Рекомендуемый формат: **WebP** или **JPG 80–85% качества**
- Размер файла: старайся держать до **200 KB** для обложек и **150 KB** для галереи

### Cover в раскрытом проекте

То же изображение, что и обложка, растягивается на всю ширину. Для 21:9 соотношения:

- **1920 × 823 px** — обычный экран
- **2400 × 1030 px** — для Retina / 4K

### Сжатие изображений

Можно использовать:

- **Squoosh** — https://squoosh.app
- **TinyPNG** — https://tinypng.com
- **ImageOptim** (macOS)
- **Photoshop** — Export → Save for Web

Если не заданы — используются токены по умолчанию.

## Публикация (GitHub Pages)

Сайт публикуется автоматически при мердже в `main` — в релиз уходит только смерженное.

### Ветки

| Ветка | Назначение |
|-------|------------|
| `dev` | Рабочая ветка: новые проекты, правки контента, эксперименты |
| `main` | Релизная ветка. Пуш или мердж в `main` → сборка и деплой на GitHub Pages |

Рабочий процесс: правки в `dev` → проверка локально (`npm run dev`) → pull request или мердж `dev` в `main` → автодеплой.

### Как это устроено

- `.github/workflows/deploy.yml` — GitHub Actions: `npm ci` → `npm run build` → публикация `dist/` на Pages. Запускается только на пуш в `main`.
- `base: '/Portfolio-oriamio/'` в `vite.config.ts` — префикс адреса страницы проекта.
- `postbuild` копирует `index.html` → `404.html` — чтобы прямые ссылки на `/projects/...` работали на GitHub Pages (SPA-роутинг).
- Проекты с `draft: true` во frontmatter не попадают в сборку.
- Картинки автоматически оптимизируются: `scripts/optimize-images.mjs` создаёт `.webp`-дубли (quality 82, до 2800px — это покрывает Retina 2x), сайт ссылается на них, а оригиналы выкидываются из сборки. Запускается перед `dev`/`build`, вручную — `npm run optimize`. Файлы `.webp` коммитим вместе с исходниками.

### Первое включение (один раз)

В репозитории на GitHub: **Settings → Pages → Source: "GitHub Actions"**. После этого первый пуш в `main` опубликует сайт по адресу `https://olgaoriami-gif.github.io/Portfolio-oriamio/`.

### Свой домен (когда понадобится)

1. В настройках Pages указать домен (или добавить файл `public/CNAME` с именем домена).
2. В `vite.config.ts` сменить `base` на `'/'`.
3. Настроить DNS у регистратора (CNAME на `olgaoriami-gif.github.io`).
